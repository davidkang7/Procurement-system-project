담당: David Kang(강기종, davidkang@inlct.com) · 구매팀 SCM 매니저
최종 갱신: 2026-09-16 (2026-09 수작업 운영 규칙을 렌더러에 반영)

이 문서는 **사람이 지켜야 할 규칙**이고, 그 중 기계가 지킬 수 있는 부분은
`render_po.py` / `po_form.py` / `vendor_rules.json` 에 구현돼 있다.
규칙을 바꾸면 코드도 같이 바꾼다(코드가 규칙을 따라가는 쪽이다).

## 1. 프로세스 전체 흐름

```
[결재 시스템] PRC 최종승인(최종승인(PRC))
      │  Code.gs _processPdfAndConsolidateJob 말미
      ▼
[GAS] PO.gs _preparePoHandoff_()
      · FINAL/{PO} 폴더에 po_manifest.json 기록 (품의서 원본 값만)
      · 주문서목록 시트에 행 등록 — 상태 '생성대기'
      · David에게 "주문서 생성 요청" 메일
      ▼
[로컬] po-renderer/render_po.py --folder <FINAL/{PO} 폴더>
      · 2026 기준 양식에 값 기입 → Excel COM 재계산 → PDF
      · 자체 검증(합계·양식 잔재·로고·### ·페이지 구성)
      · 주문서 폴더에 {PO번호}_{업체명}.xlsx + .pdf 업로드
      ▼
[사람] PDF 육안 확인 → GAS에서 markPoDone("prcToken", "파일ID")
      · 주문서목록 상태 '생성완료' + 파일ID·링크·시각·실행자 기록
```

### 어디에 어떻게 기록되는가

| 단계 | 기록 위치 |
|---|---|
| 결재 완료 | `품의서목록` — R열 `최종승인(PRC)`, Z열 `FINAL`, T열 FINAL 폴더 ID |
| 주문서 생성 요청 | `주문서목록` 행 추가(상태 `생성대기`) + FINAL/{PO}의 `po_manifest.json` + 요청 메일 + 시스템로그 `PO_HANDOFF` |
| 주문서 생성 완료 | `주문서목록` 상태 `생성완료`(xlsxFileId·xlsxUrl·generatedAt·generatedBy) + 시스템로그 `PO_GENERATED` |

관리자 콘솔 함수 — `listPoPending()` 미생성 목록 / `backfillPoSheet()` 과거 건 채우기
/ `rerunPoHandoff("prcToken")` 요청 재생성. 모두 관리자(ADMIN_EMAILS) 전용이다.

결재를 거치지 않은 과거 건이나 핸드오프 실패 건은 **DB 백업 경로**로 우회한다.

```
render_po.py --db "구매결재시스템_DB_YYYYMMDD.xlsx" --po TO-PO-26-278 [--po ...]
```

## 2. 입력 데이터

| 경로 | 입력 | 비고 |
|---|---|---|
| 핸드오프 | `po_manifest.json` (po-manifest-v2) | PO.gs가 기록. 품의서 화이트리스트 값만 담긴다 |
| DB 백업 | `구매결재시스템_DB_YYYYMMDD.xlsx` → `품의서목록` 탭 | `DocType=PRC`, `결재상태=최종승인(PRC)` 행 |

품목내역 형식: `1. 품명 | 단위 | N개 | 단가 KRW` (구분자가 `/` 인 옛 행도 지원)
→ **단가 × 수량의 합 = 합계금액**(부가세 별도)이어야 한다. 다르면 렌더러가 중단한다.

둘째 필드는 실무상 단위(`ea`, `1 ea`, `set`, `회`…)로 쓰이지만 옛 행에는 규격(`M8x20`)이
들어 있기도 하다. 단위로 읽히면 E열, 아니면 규격으로 보고 **품목 바로 아래 행**에 적는다.

## 3. 양식 — 2026 기준 양식만 쓴다

주문서는 **2페이지**다: 1p QF-741-2 주문서 폼 + 2p 표준거래조건.

| 구분 | 기준 양식 | 거래조건 | 품목칸 | 합계행 |
|---|---|---|---|---|
| 내자(KRW) | `templates/po_base_krw.xlsx` (= TO-PO-26-261_태성테크) | 국문 '발주서 표준거래조건' | 14~34행 | G35 |
| 외자(USD/JPY/EUR) | `templates/po_base_fx.xlsx` (= TO-PO-26-264_Coherent) | 영문 'General Terms and Conditions of Purchase' | 14~36행 | G37 |

- **업체의 옛 주문서를 복사하지 않는다.** 2026년 이전 파일에는 구주소·전임 담당자
  레터헤드가 남아 있고 거래조건 페이지가 없으며, 일부는 제목 윗부분이 잘려 있다.
  (2026-09-08에 이 실수로 재작업했다.)
- 기준 양식에는 거래조건 2p가 **이미 들어 있다** → `add_terms.py` 류를 다시 돌리지 않는다.
- 부득이 옛 양식을 써야 하면 `--base <파일>` 로 지정하되, 괘선을 Line 도형으로 그린
  양식은 저장 과정에서 괘선이 깨질 수 있다(권장하지 않음).

### 셀 맵 (QF-741-2 Rev 0)

| 셀 | 값 |
|---|---|
| `C9` | P/O-No = 품의번호 |
| `G9` | Date = 발행일자 (`yyyy-mm-dd`) |
| `C10` | Payment Terms |
| `G10` | Destination — 내자 `KOREA` / 외자 `INLC Technology, Daejeon, Korea` |
| `C11` | Reference NO.(품의번호) — **관례상 공란** |
| `C12` | Amount = `=G{합계행}` (통화 서식도 함께 갱신) |
| `G12` | Shipper = 업체 상호 표기 |
| 14행~ | `A` No · `B` DESCRIPTION · `D` 수량 · `E` 단위 · `F` 단가 · `G` `=D*F` · `H` DEL'Y DATE · `I` REMARK |
| `I14` | REMARK 라벨(업체별). 품의서에 견적번호가 없으면 **라벨만** 넣고 값은 비운다 |
| 합계행 `H` | `부가세별도`(내자 양식) — 유지 |

레터헤드(F4:F8, H6, H8)는 항상 현행 값으로 다시 쓴다. 외자는 `Contact to : David Kang`,
`C.P : 82-10-3188-3265` 로 표기한다.

통화 서식: KRW `₩#,##0` · USD `$ #,##0.00` · JPY `¥ #,##0` (`po_form.NUMBER_FORMATS`).

### 업체 표기 관례

`vendor_rules.json` 한 곳에서 관리한다 — Shipper 상호(㈜/(주) 표기 포함), REMARK 라벨
(`QUO NO.` / `견적 내역` / `QUO DATE` / `견적일자` / `Quotation No` / `일련번호`),
기본 결제조건, 결제조건 표기 변환(`NET 30` → `T/T(NET 30 day)`).
**신규 업체는 이 파일에 한 줄 추가만 하면 된다.** 미등록 업체는 품의서 업체명을 그대로
쓰고 REMARK 라벨은 생략한다(없는 값을 만들어 넣지 않는다).

## 4. 실행 환경

- Python: `po-renderer/.venv/Scripts/python.exe` (PATH에 python이 없다 — 직접 지정)
- **Pillow 필수.** 없으면 openpyxl이 저장할 때 **InLC 로고와 서명 이미지를 조용히 버린다.**
  렌더러가 시작 시 확인하고 중단하며, 저장 후에도 이미지 2개를 세어 검증한다.
- **Excel(COM) 필수.** openpyxl은 수식 캐시를 남기지 않아 값이 `0`으로 보인다 →
  `excel_finalize.ps1` 이 재계산·저장하고 PDF를 내보낸다. LibreOffice는 이 PC에 없다.
- 한글이 든 `.ps1`은 UTF-8 BOM으로 저장해야 한다 → `excel_finalize.ps1`은 **ASCII 전용**으로
  작성했다(시트는 A3 제목으로 찾는다).
- 실패 시 숨은 Excel 프로세스가 남을 수 있다. `MainWindowTitle -eq ""` 인 것만 종료한다
  (사용자가 직접 연 Excel은 제목이 있다).

## 5. 인쇄 설정 — 페이지 구성

1p 주문서 + 2p 거래조건 = **2페이지**가 목표다.

- 기준 양식 원본은 `fitToPage=True`(가로 1페이지 맞춤)이라 거래조건 마지막 줄('Effective date')이
  3페이지로 밀린다(3페이지는 그 한 줄만 있는 빈 장이 된다). 배율을 낮추고 `fitToPage=False`로
  두면 2페이지로 붙는다 — **내자 97%, 외자 85%**.
- 외자 양식은 열 폭이 넓어 배율 89% 이상에서는 **가로가 잘린다**(폼이 옆으로 쪼개짐).
  렌더러는 Excel의 세로 페이지나눔(VPageBreaks)과 페이지 수(PageSetup.Pages.Count)를 먼저
  재 보고, 가로가 잘리지 않는 설정 중 페이지 수가 가장 적은 배율을 고른다.
- 3페이지 형태(글자 크게)로 발행하려면 `--scale` 로 배율을 고정하거나 `po_form.PAGE_SCALES`를 조정한다.
- `verticalCentered=False`(내용이 페이지 중앙에 뜨는 현상 방지), `fitToHeight=0`(여러 페이지 허용)은 항상 강제.
- 배율을 직접 정하려면 `--scale 95`.

## 6. 검증 (생성 시 자동)

| 항목 | 방식 | 실패 시 |
|---|---|---|
| 품목 계산합 = 품의서 합계금액 | 렌더 전 | 중단(`--force`로만 강행) |
| 기준 양식 원 업체 흔적(태성테크/COHERENT/기준 PO번호) | 렌더 후 셀 스캔 | 중단 |
| 로고·서명 이미지 2개 | 저장 전 | 중단 |
| 재계산 후 C12 = 품의서 합계금액 | Excel COM | 경고 |
| 열 너비 부족(`###`) | Excel COM `.Text` | 경고 |
| PDF 페이지 구성 | PDF 페이지 수 | 2p 정상 / 3p 안내 / 그 외 경고 |

**자동으로 못 잡는 것: 글자 잘림·줄바꿈.** 생성 후 PDF를 열어 품목 행·머리글·2페이지
상단과 하단을 눈으로 확인한다(단위 `SPL`, 긴 납기일 등이 잘리는 사례가 있었다).

## 8. 관리대장 업데이트 (요청 시 수작업)

`2019년~발주-입고-마감 관리대장.xlsx` → `구매품의서_2026년도` 탭.
PO번호(Q열)가 미리 채워진 예약 행에 기입한다.
`B` 기안일자 · `C` P/O일자 · `K` 결제조건 · `L` 담당자 · `P` 품의번호란(`X`) ·
`R` 결제구분(내자/외자) · `S` 거래처 · `T` 거래품명 · `U` 용도 · `V` 수량 · `W` 공급가액
(X 세액 · Y 합계는 기존 수식 유지). 여러 품목 건은 **수량 1 + 총액**으로 적는다.
